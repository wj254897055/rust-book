第 1 章

开始入门

安装 Rust，写下第一个程序，然后用 Cargo 管理真正的项目。

让我们开始你的 Rust 之旅！要学的东西很多，但每段旅程都有起点。本章将讨论：

  • 在 Linux、macOS 和 Windows 上安装 Rust
  • 编写一个打印 Hello, world! 的程序
  • 使用 Rust 的包管理器和构建系统 cargo

1.1安装

第一步是安装 Rust。我们将通过 rustup 下载 Rust——这是一个用于管理 Rust 版本及相关工具的命令行工具。下载过程需要联网。

注意如果你出于某些原因不想使用 rustup，请参阅 其他 Rust 安装方式 页面了解更多选择。

以下步骤会安装最新稳定版的 Rust 编译器。Rust 的稳定性保证意味着，本书中所有能够编译的示例，在更新的 Rust 版本中仍将继续编译。不同版本之间的输出可能略有差异，因为 Rust 经常改进错误信息和警告。换句话说，只要你按照这些步骤安装了较新的稳定版 Rust，本书内容应当能按预期工作。

命令行记号

在本章以及全书中，我们会展示一些在终端中使用的命令。凡是需要你在终端中输入的行，都以 $ 开头。你不需要输入 $ 字符；它只是表示每条命令开始处的命令行提示符。不以 $ 开头的行通常显示上一条命令的输出。此外，PowerShell 专用示例会使用 > 而不是 $。

在 Linux 或 macOS 上安装 rustup

如果你使用的是 Linux 或 macOS，请打开终端并输入以下命令：

$ curl --proto '=https' --tlsv1.2 https://sh.rustup.rs -sSf | sh

该命令会下载一个脚本并开始安装 rustup 工具，随后由它安装最新稳定版的 Rust。系统可能会提示你输入密码。如果安装成功，会出现下面这一行：

Rust is installed now. Great!

你还需要一个链接器（linker），它是 Rust 用来把编译产物组合成一个文件的程序。你的系统很可能已经装有链接器。如果遇到链接器错误，应该安装一个 C 编译器，它通常包含链接器。C 编译器也很有用，因为一些常见的 Rust 包依赖 C 代码，需要 C 编译器才能构建。

在 macOS 上，可以通过以下命令安装 C 编译器：

$ xcode-select --install

Linux 用户通常应根据所用发行版的文档安装 GCC 或 Clang。例如，如果你使用的是 Ubuntu，可以安装 build-essential 包。

在 Windows 上安装 rustup

在 Windows 上，请访问 https://www.rust-lang.org/tools/install 并按照页面说明安装 Rust。安装过程中的某个阶段会提示你安装 Visual Studio，它提供编译程序所需的链接器和本机库。如果这一步需要更多帮助，请参阅 https://rust-lang.github.io/rustup/installation/windows-msvc.html。

本书其余部分使用的命令在 cmd.exe 和 PowerShell 中都能运行。如果存在特定差异，我们会说明应该使用哪一个。

故障排查

要检查 Rust 是否安装正确，请打开 shell 并输入：

$ rustc --version

你应该会看到最新稳定版的版本号、提交哈希和提交日期，格式如下：

rustc x.y.z (abcabcabc yyyy-mm-dd)

如果看到这些信息，说明 Rust 已成功安装！如果没有看到，请按下面的方法检查 Rust 是否位于 %PATH% 系统变量中。

在 Windows CMD 中，使用：

> echo %PATH%

在 PowerShell 中，使用：

> echo $env:Path

在 Linux 和 macOS 中，使用：

$ echo $PATH

如果这些都没问题，Rust 仍然无法工作，还有几个地方可以寻求帮助。你可以在 社区页面 找到如何联系其他 Rustacean（我们给自己的一个俏皮称呼）的方法。

更新与卸载

通过 rustup 安装 Rust 后，更新到新发布的版本很简单。在 shell 中运行以下更新脚本：

$ rustup update

要卸载 Rust 和 rustup，请在 shell 中运行以下卸载脚本：

$ rustup self uninstall

阅读本地文档

Rust 安装时也会包含一份本地文档副本，方便你离线阅读。运行 rustup doc 即可在浏览器中打开本地文档。

每当标准库提供了某个类型或函数，而你不确定它做什么、怎么用时，就去查应用程序编程接口（API）文档！

使用文本编辑器与 IDE

本书不假定你使用什么工具编写 Rust 代码。几乎任何文本编辑器都能完成工作！不过，许多文本编辑器和集成开发环境（IDE）都内置了 Rust 支持。你总能在 Rust 官网的 工具页面 找到一份相当新的编辑器与 IDE 列表。

离线使用本书

在若干示例中，我们会用到标准库之外的 Rust 包。要完成这些示例，你要么需要联网，要么需要提前下载好这些依赖。要提前下载依赖，可以运行以下命令。（我们会在后文详细解释 cargo 是什么，以及这些命令分别做了什么。）

$ cargo new get-dependencies
$ cd get-dependencies
$ cargo add rand@0.10.1 trpl@0.2.0

这会把相关包的下载内容缓存起来，之后就不必再次下载。运行完这些命令后，你不需要保留 get-dependencies 文件夹。如果你已经运行过这条命令，就可以在本书其余部分的所有 cargo 命令中加上 --offline 标志，使用这些缓存版本，而不是尝试联网。

1.2Hello, World!

现在你已经安装了 Rust，是时候编写第一个 Rust 程序了。学习一门新语言时，传统做法是写一个在屏幕上打印 Hello, world! 的小程序，我们这里也照做！

注意本书假定你对命令行有基本了解。Rust 对你的编辑工具、开发工具或代码存放位置没有特别要求，所以如果你更喜欢使用 IDE 而不是命令行，尽管使用你喜欢的 IDE。许多 IDE 现在都对 Rust 有一定程度的支持；详情请查看 IDE 的文档。Rust 团队一直致力于通过 rust-analyzer 提供出色的 IDE 支持。更多细节请参阅 附录 D。

项目目录设置

首先创建一个目录来存放 Rust 代码。Rust 并不关心代码放在哪里，但为了本书中的练习和项目，我们建议在主目录下创建一个 projects 目录，并把所有项目都放在那里。

打开终端，输入以下命令，创建一个 projects 目录，并在其中创建 “Hello, world!” 项目的目录。

在 Linux、macOS 和 Windows 的 PowerShell 中，输入：

$ mkdir ~/projects
$ cd ~/projects
$ mkdir hello_world
$ cd hello_world

在 Windows CMD 中，输入：

> mkdir "%USERPROFILE%\projects"
> cd /d "%USERPROFILE%\projects"
> mkdir hello_world
> cd hello_world

Rust 程序基础

接下来新建一个源文件，命名为 main.rs。Rust 文件始终以 .rs 扩展名结尾。如果文件名中包含多个单词，惯例是用下划线分隔。例如，使用 hello_world.rs，而不是 helloworld.rs。

现在打开刚刚创建的 main.rs，输入代码清单 1-1 中的内容。

文件名：main.rs

fn main() {
    println!("Hello, world!");
}

代码清单 1-1：一个打印 Hello, world! 的程序

保存文件，回到终端，并确保当前位于 ~/projects/hello_world 目录。在 Linux 或 macOS 上，输入以下命令来编译并运行文件：

$ rustc main.rs
$ ./main
Hello, world!

在 Windows 上，请使用 .\main 代替 ./main：

> rustc main.rs
> .\main
Hello, world!

无论使用哪种操作系统，终端都应该打印出字符串 Hello, world!。如果没有看到这个输出，请回到安装部分的“故障排查”寻找帮助。

如果打印出了 Hello, world!，恭喜！你已经正式写下了一个 Rust 程序。这让你成为一名 Rust 程序员——欢迎加入！

Rust 程序的解剖

让我们详细回顾这个 “Hello, world!” 程序。下面是第一块拼图：

fn main() {

}

这几行定义了一个名为 main 的函数。main 函数很特殊：在每个可执行的 Rust 程序中，它总是最先运行的代码。这里，第一行声明了一个名为 main、没有参数、也不返回值的函数。如果有参数，它们会放在括号（()）中。

函数体包裹在 {} 中。Rust 要求所有函数体都使用花括号。良好的风格是把左花括号放在函数声明同一行，并在两者之间留一个空格。

注意如果你想让 Rust 项目保持统一的代码风格，可以使用名为 rustfmt 的自动格式化工具，按特定风格格式化代码（关于 rustfmt 的更多内容见 附录 D）。Rust 团队已将此工具与 rustc 一起纳入标准 Rust 发行版，所以它应该已经安装在你的电脑上了！

main 函数体包含以下代码：

println!("Hello, world!");

这一行完成了这个小程序的全部工作：把文本打印到屏幕上。这里有三个重要细节需要注意。

第一，println! 调用的是一个 Rust 宏。如果它调用的是函数，写法会是 println（不带 !）。Rust 宏是一种编写“生成代码的代码”的方式，用于扩展 Rust 语法，我们会在 第 20 章 详细讨论。现在你只需要知道，! 表示你调用的是宏而不是普通函数，而且宏并不总是遵循与函数相同的规则。

第二，你看到了 "Hello, world!" 字符串。我们把这个字符串作为参数传给 println!，它会被打印到屏幕上。

第三，这一行以分号（;）结尾，表示这个表达式已经结束，下一个表达式可以开始。大多数 Rust 代码行都以分号结尾。

编译与执行

你刚刚运行了一个新建的程序，现在让我们仔细看看这个过程。

运行 Rust 程序之前，必须先使用 Rust 编译器编译它：输入 rustc 命令，并把源文件名传给它，像这样：

$ rustc main.rs

如果你有 C 或 C++ 背景，会发现这和 gcc 或 clang 很像。编译成功后，Rust 会输出一个二进制可执行文件。

在 Linux、macOS 和 Windows 的 PowerShell 中，可以在 shell 里输入 ls 查看可执行文件：

$ ls
main  main.rs

在 Linux 和 macOS 上，你会看到两个文件。在 Windows 的 PowerShell 中，你会看到与 CMD 相同的三个文件。在 Windows 的 CMD 中，应输入：

> dir /B %= /B 选项表示只显示文件名 =%
main.exe
main.pdb
main.rs

这里显示了扩展名为 .rs 的源代码文件、可执行文件（Windows 上是 main.exe，其他平台上是 main），以及在 Windows 上包含调试信息的 .pdb 文件。接下来，像这样运行 main 或 main.exe：

$ ./main # 在 Windows 上使用 .\main

如果你的 main.rs 就是那个 “Hello, world!” 程序，这一行会在终端打印 Hello, world!。

如果你更熟悉 Ruby、Python 或 JavaScript 这类动态语言，可能不习惯把编译和运行分成两步。Rust 是一门提前编译（ahead-of-time compiled）的语言，这意味着你可以编译程序，然后把可执行文件交给别人，即使对方没有安装 Rust 也能运行。如果你给别人一个 .rb、.py 或 .js 文件，对方需要分别安装 Ruby、Python 或 JavaScript 的实现。但在那些语言中，你只需要一条命令就能编译并运行程序。语言设计中的一切都是权衡。

对于简单程序，只用 rustc 编译就够了；但随着项目变大，你会希望管理各种选项，并让代码更容易分享。接下来，我们将介绍 Cargo 工具，它会帮助你编写真实世界中的 Rust 程序。

1.3Hello, Cargo!

Cargo 是 Rust 的构建系统和包管理器。大多数 Rustacean 使用这个工具管理 Rust 项目，因为 Cargo 会替你处理许多任务，比如构建代码、下载代码依赖的库，以及构建这些库。（我们把代码所需的库称为依赖（dependencies）。）

最简单的 Rust 程序，比如我们目前写的这个，没有任何依赖。如果我们用 Cargo 构建 “Hello, world!” 项目，它只会用到 Cargo 中负责构建代码的那部分。随着你编写更复杂的 Rust 程序，你会添加依赖；而如果用 Cargo 创建项目，添加依赖会容易得多。

由于绝大多数 Rust 项目都使用 Cargo，本书其余部分也假定你在使用 Cargo。如果你使用安装部分介绍的官方安装程序安装 Rust，Cargo 会随 Rust 一起安装。如果你通过其他方式安装 Rust，可以在终端输入以下命令，检查 Cargo 是否已安装：

$ cargo --version

如果看到版本号，说明已经安装！如果看到错误，比如 command not found，请查阅你所使用安装方式的文档，了解如何单独安装 Cargo。

使用 Cargo 创建项目

让我们用 Cargo 创建一个新项目，并看看它与原来的 “Hello, world!” 项目有什么不同。回到 projects 目录（或者你存放代码的其他目录），然后在任意操作系统上运行：

$ cargo new hello_cargo
$ cd hello_cargo

第一条命令会创建一个名为 hello_cargo 的新目录和项目。我们把项目命名为 hello_cargo，Cargo 会在同名目录中创建它的文件。

进入 hello_cargo 目录并列出文件。你会看到 Cargo 为我们生成了两个文件和一个目录：一个 Cargo.toml 文件，以及一个包含 main.rs 的 src 目录。

它还初始化了一个新的 Git 仓库，以及一个 .gitignore 文件。如果在已有的 Git 仓库中运行 cargo new，则不会生成 Git 文件；你可以使用 cargo new --vcs=git 覆盖这一行为。

注意Git 是一种常见的版本控制系统。你可以使用 --vcs 标志，让 cargo new 使用其他版本控制系统，或者不使用版本控制。运行 cargo new --help 查看可用选项。

用你喜欢的文本编辑器打开 Cargo.toml。它应该与代码清单 1-2 类似。

文件名：Cargo.toml

[package]
name = "hello_cargo"
version = "0.1.0"
edition = "2024"

[dependencies]

代码清单 1-2：cargo new 生成的 Cargo.toml 内容

这个文件采用 TOML（Tom's Obvious, Minimal Language，Tom 的直观极简语言）格式，这是 Cargo 的配置格式。

第一行 [package] 是一个节标题，表示接下来的语句正在配置一个包。随着我们向这个文件添加更多信息，还会加入其他节。

接下来的三行设置了 Cargo 编译程序所需的配置信息：名称、版本，以及要使用的 Rust Edition。我们会在 附录 E 讨论 edition 键。

最后一行 [dependencies] 是一个节的开始，用于列出项目的依赖。在 Rust 中，代码包被称为 crate。这个项目不需要其他 crate，但第 2 章的第一个项目会用到，所以届时我们会使用这个依赖节。

现在打开 src/main.rs 看看：

文件名：src/main.rs

fn main() {
    println!("Hello, world!");
}

Cargo 已经为你生成了一个 “Hello, world!” 程序，就像我们在代码清单 1-1 中写的一样！到目前为止，我们的项目与 Cargo 生成的项目之间的区别是：Cargo 把代码放在 src 目录中，并且顶层目录里有一个 Cargo.toml 配置文件。

Cargo 期望源文件位于 src 目录中。顶层项目目录只用于 README、许可证信息、配置文件，以及其他与代码无关的内容。使用 Cargo 有助于组织项目。每个东西都有自己的位置，而每个东西都在自己的位置上。

如果你像我们创建 “Hello, world!” 项目那样，创建了一个不使用 Cargo 的项目，也可以把它转换成使用 Cargo 的项目。把项目代码移到 src 目录，并创建一个合适的 Cargo.toml 文件。获得这个 Cargo.toml 的一个简单方法是运行 cargo init，它会自动为你创建。

构建并运行 Cargo 项目

现在来看看用 Cargo 构建并运行 “Hello, world!” 程序时有什么不同！在 hello_cargo 目录中，输入以下命令构建项目：

$ cargo build
   Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo)
    Finished dev [unoptimized + debuginfo] target(s) in 2.85 secs

这条命令会在 target/debug/hello_cargo（Windows 上是 target\debug\hello_cargo.exe）中创建可执行文件，而不是在当前目录中。由于默认构建是调试构建，Cargo 会把二进制文件放在名为 debug 的目录里。你可以用以下命令运行它：

$ ./target/debug/hello_cargo # 在 Windows 上使用 .\target\debug\hello_cargo.exe
Hello, world!

如果一切顺利，终端应该打印 Hello, world!。第一次运行 cargo build 还会让 Cargo 在顶层创建一个新文件：Cargo.lock。这个文件记录项目中依赖的精确版本。这个项目没有依赖，所以文件内容很少。你永远不需要手动修改这个文件；Cargo 会替你管理它的内容。

我们刚刚用 cargo build 构建了项目，并用 ./target/debug/hello_cargo 运行它；不过也可以使用 cargo run，用一条命令完成编译并运行生成的可执行文件：

$ cargo run
    Finished dev [unoptimized + debuginfo] target(s) in 0.0 secs
     Running `target/debug/hello_cargo`
Hello, world!

使用 cargo run 比记住先运行 cargo build、再使用完整路径运行二进制文件方便得多，所以大多数开发者会使用 cargo run。

注意，这一次没有看到 Cargo 正在编译 hello_cargo 的输出。Cargo 发现文件没有变化，所以没有重新构建，而是直接运行了二进制文件。如果你修改了源代码，Cargo 会在运行前重新构建项目，你会看到类似这样的输出：

$ cargo run
   Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo)
    Finished dev [unoptimized + debuginfo] target(s) in 0.33 secs
     Running `target/debug/hello_cargo`
Hello, world!

Cargo 还提供了 cargo check 命令。这个命令会快速检查代码，确保它可以编译，但不生成可执行文件：

$ cargo check
   Checking hello_cargo v0.1.0 (file:///projects/hello_cargo)
    Finished dev [unoptimized + debuginfo] target(s) in 0.32 secs

为什么可能不想要可执行文件呢？通常，cargo check 比 cargo build 快得多，因为它跳过了生成可执行文件的步骤。如果你在写代码时持续检查工作成果，使用 cargo check 可以更快地告诉你项目是否仍能编译！因此，许多 Rustacean 在写程序时会定期运行 cargo check，确认代码可以编译；等到准备使用可执行文件时，再运行 cargo build。

让我们回顾一下目前学到的 Cargo 知识：

  • 可以使用 cargo new 创建项目。
  • 可以使用 cargo build 构建项目。
  • 可以使用 cargo run 一步完成构建并运行。
  • 可以使用 cargo check 构建项目而不生成二进制文件，以检查错误。
  • Cargo 不把构建结果保存在代码所在目录，而是放在 target/debug 目录中。

使用 Cargo 的另一个好处是，无论使用哪种操作系统，命令都相同。因此，从现在开始，我们不再分别提供 Linux/macOS 与 Windows 的特定说明。

构建发布版本

当项目终于准备发布时，可以使用 cargo build --release 以优化方式编译它。这条命令会在 target/release 而不是 target/debug 中创建可执行文件。优化会让 Rust 代码运行得更快，但开启优化会延长编译时间。这就是为什么有两种不同的配置（profile）：一种用于开发，此时你希望快速、频繁地重新构建；另一种用于构建最终交给用户的程序，这个程序不会被反复重新构建，并且要尽可能快地运行。如果你要对代码的运行时间做基准测试，务必运行 cargo build --release，并使用 target/release 中的可执行文件进行测试。

利用 Cargo 的约定

对于简单项目，Cargo 相比直接使用 rustc 并没有带来太多价值，但随着程序变得更复杂，它会证明自己的价值。一旦程序增长到多个文件或需要依赖，让 Cargo 协调构建就会容易得多。

尽管 hello_cargo 项目很简单，但它现在已经用到了你今后 Rust 生涯中会使用的许多真实工具。事实上，要处理任何现有项目，你都可以使用以下命令通过 Git 检出代码、切换到该项目目录并构建：

$ git clone example.org/someproject
$ cd someproject
$ cargo build

有关 Cargo 的更多信息，请查看 它的文档。

小结

你的 Rust 之旅已经有了一个很好的开始！在本章中，你学会了如何：

  • 使用 rustup 安装最新稳定版的 Rust。
  • 更新到更新的 Rust 版本。
  • 打开本地安装的文档。
  • 直接使用 rustc 编写并运行 “Hello, world!” 程序。
  • 按照 Cargo 的约定创建并运行新项目。

现在是构建一个更完整的程序、熟悉 Rust 代码读写的好时机。因此，第 2 章我们将构建一个猜数字游戏。如果你更愿意先学习 Rust 中常见的编程概念，可以先阅读 第 3 章， 然后再回到 第 2 章。
